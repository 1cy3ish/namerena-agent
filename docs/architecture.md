# 基础架构

## 共享知识

`knowledge/` 是领域事实、术语和来源的共同入口。用 Markdown 与 JSON 便于人工核查和 Git 审阅；`knowledge/official/` 保留正文快照与结构化索引，`data/raw/official-namerena/` 保留纳入 Git 的原始官方字节，二者通过来源与哈希关联。

`scripts/` 使用 Python 标准库抓取、提取和校验资料，不决定未来应用运行语言。官方提取出的词条可重新生成，人工词条和维护者提供的信息单独维护。

工具实现另存于 `knowledge/tools/`，以固定提交和证据范围补充官方基础层。`terminology.json` 保存新增词条与语境补充，生成总表时统一合并，不反向修改官方页面快照；同一别名可按语境指向不同概念。

社区资料存于 `knowledge/community/`，记录称呼约定、页面和帖子观察、读取楼号及时间限制。社区和工具目录的词条一起合并到总表；活动和榜单字段不反向推定为游戏引擎机制。

## 接入层

- `skills/`：按问题加载知识的领域指引，当前仅支持在本仓库中读取共享资料；独立发布需打包知识依赖。
- `agents/`：问答任务的角色提示词和回答约定，可由不同机器人运行时适配。
- `mcp/`：为 AI 客户端提供统一检索能力的设计与未来实现。
- `evals/`：来自实际用例的术语理解、来源引用、版本辨析和未知问题样例。

当前依赖方向为：skill、agent 和未来 MCP 读取共享知识；问答评估检查最终行为。运行时、模型和存储引擎尚未选定。

## 增长顺序

1. 完成有来源、有语境的黑话和概念整理。
2. 实现术语别名匹配、知识检索与引用解析。
3. 封装 MCP，再适配问答机器人和工具开发者的使用流程。
4. 有明确需求时，单独验证并接入模拟、评分或测号工具。

引擎行为、具体版本和评分工具元数据属于后续独立核查内容；初始化阶段保留入口与问题，不先承诺未经验证的执行能力。
